### 方向三：多Agent协作架构

**状态**：❌ 未实现

#### 交叉验证是伪验证

`auto_analyzer.py:179`：

```python
cv = {
    '旺衰': {'primary': '...', 'secondary': '待盲派验证', 'result': '✅'},
    ...
    'divergence': ''
}
```

- `secondary` 写"待盲派验证""待验证"，但 `result` 已写成 `✅`
- `divergence` 为空
- **没有实际执行任何交叉验证逻辑**

这个展示会让用户误以为系统完成了双体系验证。建议在第二套推理体系真正实现前，将 `result` 改为 `⏳未执行`。

## 第三章：修改建议（按实际收益排序）

### P0-A：评测可靠性（修复后再评测）

#### 1. 修复 RAG 测试回归
统一 `option_evidence()` 接口，跑完整非 E2E 测试。当前基线不全绿时，不应继续叠加新架构。

#### 2. 抗位置偏差（Phase 3 核心）
不单纯增加 few-shot，而是采用**内容评分法**：
- 让模型逐项输出"选项内容、支持证据、反证、分数"
- 按最高分映射字母
- 同一题用**至少 3 个**不同 shuffle seed 验证一致性
- 隔离 API 失败、空响应、解析失败、回映射失败，分别统计

#### 3. 多 seed 配对评测
明确的验收条件：

| 条件 | 阈值 |
|------|------|
| shuffle seed 数量 | ≥3 |
| 同一题跨排列一致率 | ≥80% |
| shuffle gap（shuffle-on/off 差） | ≤3pp |
| API 失败 | 单独统计 |
| 空响应 | 单独统计 |
| 解析失败 | 单独统计 |
| 回映射失败 | 单独统计 |
| A0 vs A4 比较 | 只在配对成功样本上比较；报告置信区间或 McNemar 检验 |

---

### P0-B：命理能力（提升核心判断）

#### 4. 建立命理引擎专项标准集

**标注协议**：
- **试标阶段**：先取 10~15 例试标，修订标签规范和枚举定义，完成后冻结规范
- **正式阶段**：双专家独立标注，分歧提交仲裁
- 旺衰、格局、用神枚举定义在试标后冻结，正式标注过程中不再修改
- 每项需记录证据字段（从 chart 数据中提取）
- 专家一致率目标 ≥85%（Cohen's Kappa ≥0.7；多标签用神按 top-1 严格匹配；部分一致不计入）
- dev/test 严格隔离，禁止在最终测试集上反复调试

**覆盖范围**（50~100 例）：
- 旺衰等级分类
- 正格、从格、专旺格、化气格判定
- 用神 top-1、top-2
- 破格与救应判断
- 大运流年方向

#### 5. 旺衰和从格联合引擎（一起实现）
从格依赖旺衰极端程度、根气、印比、财官食伤成势和破格条件。**不能先写几个简单 `if` 判断**，否则会把普通身弱误判为从格。

每个判断输出应包含：候选格局、成格条件、破格条件、支持证据、反证、置信度。

#### 6. 扩展报告硬规则校验
下一批高价值规则：
- 十神与日主阴阳五行一致性
- 三合/三会/六合/合化成立条件
- 从格破格条件
- 旺衰结论与用神方向冲突
- 月令格局与透干条件
- 大运十神计算一致性
- 前后段落结论矛盾

---

### P0-C：产品可信度修复

#### 7. 移除伪交叉验证状态
cross_validation 在 `result` 中展示 `✅` 但 `secondary` 写"待验证"，直接误导用户以为系统完成了双体系验证。

在第二套推理体系真正实现前，将 `result` 从 `✅` 改为 `⏳未执行`，`divergence` 标注 `N/A`。短期可先做确定性规则校验器，不必立即上多Agent。

---

### P2：暂缓

#### 8. Graph RAG 和完整多Agent 暂缓
当前没有证据表明引入图数据库或更多 Agent 会直接提高准确率。它们会增加成本和错误传播。

优先完成：结构化命盘规则 → 标准集 → 检索消融。

---

### 持续：统一验收指标

后续报告应同时提供：
- BaziQA shuffle-off/on repeats=3
- MingLi-Bench 完整集（非 smoke）
- 旺衰/格局/用神专项准确率
- 检索 Hit@K、MRR
- 真实报告硬错率
- 人工盲审一致率
