| 模型 | 格局识别 | 用神判断 | 综合准确率 |

## 3. 六大提升方向

### 方向一：深化本地推理引擎（可预期提升：10.6% → 25%+）

当前 `auto_analyzer.py` 的本地分析仅做简单百分比判定。需要升级：

#### 1.1 旺衰量化升级为计分制

```
当前：得令/得地/得势 → 百分比 → 5档（身旺/强/中和/弱/真弱）
升级：
  天干透出 ×5.0 分
  地支本气 ×4.0 分
  地支中气 ×2.0 分
  地支余气 ×1.0 分
  月令 (得令) ×1.5 乘数
  三合局 +15 分
  三会局 +20 分
  六合 +8 分
  十二长生 (临官/帝旺额外加分)
  → 总分判定：身极旺 / 身旺 / 中和 / 身弱 / 身极弱 / 从格判定线
```

#### 1.2 格局系统扩展

```
当前：月令本气透干 → 8种正格
升级：
  ├─ 正格（8种）：月令本气/中气透干
  ├─ 变格覆盖：
  │   ├─ 从格：从强 / 从杀 / 从财 / 从儿 / 从势
  │   ├─ 化气格：甲己化土 / 乙庚化金 / 丙辛化水 / 丁壬化木 / 戊癸化火
  │   ├─ 专旺格：曲直 / 炎上 / 稼穑 / 从革 / 润下
  │   └─ 两神成象格
  └─ 格局破格/救应检测
```

#### 1.3 用神系统升级（五层优先级）

```
当前：身旺→克泄耗，身弱→生扶（仅扶抑法）
升级：
  第1优先级：调候用神（《穷通宝鉴》）
  第2优先级：扶抑用神（身旺/弱 → 克泄耗/生扶）
  第3优先级：通关用神（解决「两神相战」）
  第4优先级：病药用神（针对特殊格局异常）
  第5优先级：格局用神（正官格→财印辅助等）
```

### 方向二：构建命理知识图谱（Graph RAG） (可预期提升：准确率 +15~20%)

当前知识库是扁平 JSON 文件，无法实现多跳推理。建议升级为知识图谱：

#### 2.1 命理知识图谱结构

```
节点类型：
  ├─ 概念节点（十神、五行、神煞、格局...）
  ├─ 古籍节点（子平真诠、滴天髓、穷通宝鉴、三命通会...）
  ├─ 案例节点（134 真实案例 + 更多采集）
  └─ 规则节点（baziqa_rules 扩展）

关系类型：
  ├─ 概念间：生成/克制/合化/冲刑
  ├─ 概念→古籍：出处引用
  ├─ 案例→事件：发生/验证
  └─ 规则→条件：适用/触发
```

#### 2.2 实现方案

```
技术栈：
  └─ NetworkX + spaCy (轻量 NER) → 构建图谱
  └─ Neo4j / KuzuDB → 生产级存储与图遍历
  └─ LightRAG / GraphRAG → 检索增强

查询流程：
  用户输入 → NER 提取关键概念 → 图谱多跳检索
  → 返回 1) 相关经典引用 2) 相似历史案例 3) 适用规则
  → 注入 LLM prompt
```

#### 2.3 行业验证

蚂蚁集团：传统 RAG (60%) → LightRAG 知识图谱 (95%)，提升 **35 个百分点**。

### 方向三：多 Agent 协作架构 (可预期提升：推理能力 +10~15%)

参考 Tianfu Agent 的多流派交叉验证模式。

#### 3.1 Agent 分工

```
主控 Agent (Orchestrator)
  ├─ 排盘 Agent：八字计算 + 校验
  ├─ 子平 Agent：《子平真诠》体系 → 格局/用神/十神
  ├─ 盲派 Agent：宾主理论/带象法/应期 → 具体事件推解
  ├─ 紫微 Agent：十二宫星曜 + 四化 → 健康/婚姻专项
  ├─ 校验 Agent：交叉比对结论，标记冲突/不一致
  └─ 结论 Agent：融合多流派意见，生成最终报告
```

#### 3.2 交叉验证机制

```
当子平 Agent 结论 ≠ 盲派 Agent 结论：
  → 激活冲突分析模式
  → 列出双方论据（来自 chart 的具体数据）
  → 标注"需要人工复核"
  → 如一方置信度更高，建议采纳并说明理由
```

### 方向四：构建标准化评测体系 (可预期：量化衡量所有改进)

#### 4.1 三层评测架构

```
L1 - 自动化规则检验 (自动化，每日跑)
  ├─ 用神五行一致性（身旺→克泄耗，身弱→生扶）
  ├─ 格局与月令匹配（正官格必须月令为官杀）
  ├─ 大运十神与事件对齐（v2 增强版）
  └─ 报告结构完整性检查

L2 - 标准题库评测 (自动化，每次发版跑)
  ├─ 接入 MingLi-Bench (160道选择题)
  ├─ 自建内部题库（134案例总结的判断题）
  └─ A/B 测试框架（对比不同 prompt 版本）

L3 - 人工盲审 (每季度跑)
  ├─ 3 位命理师独立打分
  ├─ 52 经典命例（Deep Oracle 方案）
  └─ 维度：格局 / 用神 / 大运 / 流年 / 专项事件
```

### 方向五：增强提示词工程 (可预期提升：一致性 +5~8%)

#### 5.1 动态 Prompt 选择

```
当前：所有模式模板全部注入（~20KB），浪费 token
升级：
  └─ 根据问题类型动态选择：
      ├─ 通用命盘 → mode1 + core_rules + structured_reasoning
      ├─ 合婚 → mode2 + hehun 知识库
      ├─ 流年 → mode3 + liunian_calendar
      └─ 仅回答具体问题 → 精简 prompt + 精准 context
```

#### 5.2 少样本示例 (Few-Shot)

```
注入 3-5 个已标注的【正确分析案例】作为示例：
  输入 → 推理链 → 结论
  让 LLM 模仿推理深度和格式
```

#### 5.3 推理链强化

```
当前：structured_reasoning_v1.md 定义 6 层推理但未强制
升级：
  └─ 每个分析点都要求输出：
      1)【观察】：从 chart 中提取的具体数据
      2)【推理】：命理规则 + 逻辑推演
      3)【结论】：基于以上推理的论断
      4)【置信度】：high / medium / low
```

### 方向六：数据驱动持续优化 (可预期：长期持续提升)

#### 6.1 案例数据库扩展

```
当前：134 案例（仅 13 例有时辰）
扩展：
  ├─ 从公开历史名人生日采集（已有基础）
  ├─ 增加时辰推断算法（通过重大事件反向推算）
  ├─ 用户脱敏反馈数据回写案例库
  └─ 目标：500+ 案例，50+ 完整时辰
```

#### 6.2 RLHF 反馈闭环

```
用户对报告的评分/反馈
  → feedback 表积累
  → feedback_analysis.py 识别薄弱维度
  → 针对性调整该维度的 system prompt
  → A/B 测试验证效果
  → 部署
```

#### 6.3 多模型组合策略

```
根据任务类型路由：
  ├─ 格局/用神判断 → 最强推理模型 (GPT-5.4 / Claude Opus)
  ├─ 文本润色 → 性价比模型 (Claude Sonnet)
  ├─ 古文理解 → 中文优化模型 (DeepSeek)
  └─ 交叉验证 → 双模型互审
```
