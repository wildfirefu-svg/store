## 2. 权限隔离机制（v1.1 修订，可执行）

**原则**：权限隔离必须由**技术边界**实现，不能依赖"代理自律"或"共享工作区中的目录约定"。

### 2.1 curator 运行环境

- curator 运行在**独立任务/独立受限工作区**（与当前开发工作区物理隔离：不同工作目录、不同 git 仓库或独立 sandbox）。
- curator 任务只接收：数据位置路径 + 采集规约（sealed_marriageset_spec.md）+ 真值裁决协议；**不接收**检索策略实现、prompt、实验编排相关文件。
- curator 产出（题集、真值、访问日志）只写入 curator 工作区，**不得进入当前仓库**。

### 2.2 开发侧可见面（开发代理只能收到）

- `dataset_sha`：密封题集整体 SHA（curator 侧计算后传出）
- `n_charts` / `n_questions`：题数与分组元数据
- `grouping_meta`：按命盘分组的题目数分布（不含题目内容）
- `run_interface`：Phase 9B 盲评执行器的运行接口（输入：case 数据 + prompt 参数；输出：模型回复；**不暴露**题目、选项、真值、逐题输出）

### 2.3 盲评执行器（Phase 9B 用）

- Phase 9B 通过盲评执行器运行：开发代理提交 retriever/prompt 参数，执行器在 curator 侧（或独立执行环境）对密封集运行，只回传**聚合指标**（准确率、护栏退化率等）。
- 开发代理不能读取：题目、选项、真值、逐题模型输出。
- 执行器本身由 curator 侧维护，其代码版本 SHA 冻结并记录。

### 2.4 访问日志（权限边界产生）

- 访问日志由**文件系统/权限层**产生：curator 工作区的读取/写入操作记录（谁、何时、路径、范围），不由代理自报。
- 当前开发任务若接触密封集任何内容（含通过环境变量/共享目录间接接触），即视为泄漏：密封集降级为确认集并如实记录。

### 2.5 数据位置交付

- **curator 数据位置只能提供给独立受限 curator 任务**，不得发到当前开发任务（本记录即当前开发任务的可见面，不含数据路径）。

## 3. 真值流程（冻结）

curator 一审 → 人类复核 → 分歧裁决记录 → 真值冻结（SHA 落盘于 curator 工作区）。

## 4. 采集产物（curator 侧）

- 密封题集文件（题目/选项/真值/出生信息）——curator 工作区，不进仓库
- 访问日志——权限边界产生
- 真值核验记录（分歧清单 + 裁决理由）
- A6 去重比对报告（与 Phase 7 32 盘出生信息逐盘比对）
- dataset_sha / n_charts / n_questions / grouping_meta——传开发侧（§2.2 可见面）
