## 执行摘要

### 核心结论

**工程基础设施提高，但整体命理准确率没有被证明提高。**

| 指标 | 当前值 | 说明 |
|------|--------|------|
| BaziQA shuffle-off 40×3 | 28.3% | deepseek-v4-flash + option_grounded_tfidf |
| BaziQA shuffle-on 40×3 | 18.3% | 下降 10pp，暴露强位置偏差 |
| MingLi-Bench | 60.0% | 仅前20题 smoke，非160题完整集 |
| 从格功能覆盖率 | 0% | 未实现从格检测逻辑 |

> **关于28.3%与此前30%的对比**：28.3% 使用 deepseek-v4-flash + option_grounded_tfidf，此前 30.0% 使用 deepseek-v4-pro + rag-structured。模型、Prompt 和检索方式均不同，不能据此判断提升或退化。

### 提高 vs 未提高

| 维度 | 结论 | 说明 |
|------|------|------|

## 第一章：六大方向详细评估

### 方向一：深化本地推理引擎

**整体状态**：❌ 未实现（仅用神系统有局部改善）

#### 1.1 旺衰量化

**当前实现** (`auto_analyzer.py:54`)：仍以五行占比百分比法判断旺衰，得令/得地/得势没有形成完整计算模型。

**未实现**：
- 天干透出 ×5.0 分 / 地支本气 ×4.0 分 / 中气 ×2.0 分 / 余气 ×1.0 分
- 三合局 +15 分 / 三会局 +20 分 / 六合 +8 分
- 月令得令 ×1.5 乘数
- 十二长生（临官/帝旺额外加分）
- 从格判定线

**状态**：未实现

---

#### 1.2 格局系统

**当前实现** (`auto_analyzer.py:80`)：仅月令本气十神映射，硬编码 `category: '正格'`。

**未实现**：从格（从强/从杀/从财/从儿/从势）、化气格（甲己化土等5种）、专旺格（曲直/炎上/稼穑/从革/润下）、两神成象格、破格救应检测。

**状态**：变格功能覆盖率 0%

---

#### 1.3 用神系统

`auto_analyzer.py:91` 已增加调候、扶抑、通关、病药概念，这是实际进步。但当前实现仍偏启发式：

| 层级 | 状态 | 问题 |
|------|------|------|
| 调候用神 | 已有框架 | 主要按月支查固定映射，非逐天干组合查《穷通宝鉴》原文 |
| 扶抑用神 | 已实现 | 身旺→克泄耗，身弱→生扶 |
| 通关用神 | 已有框架 | 仅检查 strongest vs wu 二维对峙 |
| 病药用神 | 已有框架 | 存在"缺什么补什么"简化倾向 |
| 格局用神 | 未实现 | 仍由身旺身弱直接映射财星/食伤/印比，未针对正官格/七杀格等具体格局选择 |

**关键缺陷**：没有处理调候用神和格局用神发生冲突时的决策规则。

**状态**：已有框架

### 方向三：多Agent协作架构

**状态**：❌ 未实现

#### 交叉验证是伪验证

`auto_analyzer.py:179`：

```python
cv = {
    '旺衰': {'primary': '...', 'secondary': '待盲派验证', 'result': '✅'},
    ...
    'divergence': ''
}
```

- `secondary` 写"待盲派验证""待验证"，但 `result` 已写成 `✅`
- `divergence` 为空
- **没有实际执行任何交叉验证逻辑**

这个展示会让用户误以为系统完成了双体系验证。建议在第二套推理体系真正实现前，将 `result` 改为 `⏳未执行`。

## 第三章：修改建议（按实际收益排序）

### P0-A：评测可靠性（修复后再评测）

#### 1. 修复 RAG 测试回归
统一 `option_evidence()` 接口，跑完整非 E2E 测试。当前基线不全绿时，不应继续叠加新架构。

#### 2. 抗位置偏差（Phase 3 核心）
不单纯增加 few-shot，而是采用**内容评分法**：
- 让模型逐项输出"选项内容、支持证据、反证、分数"
- 按最高分映射字母
- 同一题用不同 shuffle seed 验证一致性
- 隔离 API 失败与解析失败，分别统计

#### 3. 多 seed 配对评测
用至少 2 个不同 shuffle seed，验证 A0 vs A4 arm 的 shuffle-on/shuffle-off 一致性。

---

### P0-B：命理能力（提升核心判断）

#### 4. 建立命理引擎专项标准集
准备 **50~100 个专家标注命例**，覆盖：
- 旺衰等级分类
- 正格、从格、专旺格、化气格判定
- 用神 top-1、top-2
- 破格与救应判断
- 大运流年方向

#### 5. 旺衰和从格联合引擎（一起实现）
从格依赖旺衰极端程度、根气、印比、财官食伤成势和破格条件。**不能先写几个简单 `if` 判断**，否则会把普通身弱误判为从格。

每个判断输出应包含：候选格局、成格条件、破格条件、支持证据、反证、置信度。

#### 6. 扩展报告硬规则校验
下一批高价值规则：
- 十神与日主阴阳五行一致性
- 三合/三会/六合/合化成立条件
- 从格破格条件
- 旺衰结论与用神方向冲突
- 月令格局与透干条件
- 大运十神计算一致性
- 前后段落结论矛盾

---

### P1：移除错误展示

#### 7. 移除伪交叉验证状态
在第二套推理体系真正实现前，将 cross_validation 的 `result` 从 `✅` 改为 `⏳未执行`，`divergence` 标注 `N/A`。短期可先做确定性规则校验器，不必立即上多Agent。

---

### P2：暂缓

#### 8. Graph RAG 和完整多Agent 暂缓
当前没有证据表明引入图数据库或更多 Agent 会直接提高准确率。它们会增加成本和错误传播。

优先完成：结构化命盘规则 → 标准集 → 检索消融。
