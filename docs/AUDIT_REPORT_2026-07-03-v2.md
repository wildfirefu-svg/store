## 执行摘要

**工程测量能力明显提高**，但**命理判断能力只有局部提高**，尚无证据证明整体准确率提高。

| 从格识别率 | 0% | 未支持 |

#### 3.1 交叉验证是伪验证

**当前实现** (`auto_analyzer.py:179`)：

```python
cv = {
    '旺衰': {'primary': f'{grade}({dm_pct*100:.0f}%)', 'secondary': '待盲派验证', 'result': '✅'},
    '格局/层次': {'primary': pattern_name, 'secondary': '待验证', 'result': '✅'},
    ...
    'divergence': ''
}
```

- `secondary` 是"待盲派验证""待验证"——但 `result` 已写成 `✅`
- `divergence` 为空
- **没有实际执行任何交叉验证**

**问题**：这种展示会让用户误以为系统完成了双体系验证。

**建议**：在第二套推理体系真正实现前，将 `result` 改为 `⏳未执行`，不要显示勾选。

**评估**：❌ 无多Agent，交叉验证仅为展示字段

## 第三章：修改建议（按实际收益排序）

### P0：立即修复

#### 1. 修复 RAG 测试回归
- 统一 `option_evidence()` 接口，跑完整非 E2E 测试
- **当前基线不全绿时，不应继续叠加新架构**

#### 2. 移除伪交叉验证状态
- 将 `result` 从 `✅` 改为 `⏳未执行`，`divergence` 标注"N/A"
- 在第二套推理体系真正实现前，不展示假验证结果

---

### P1：高优先级（1-3周）

#### 3. 建立命理引擎专项标准集
不要直接采用未经验证的固定权重。先准备 **50~100 个专家标注命例**，覆盖：

- 旺衰等级（身极旺/身旺/中和/身弱/身极弱）
- 正格、从格（从强/从杀/从财/从儿/从势）、专旺格（曲直/炎上/稼穑/从革/润下）、化气格
- 用神 top-1、top-2
- 破格与救应
- 大运流年方向

#### 4. 旺衰和从格应一起实现（联合引擎）
从格依赖旺衰极端程度、根气、印比、财官食伤成势和破格条件。若先写几个简单 `if` 判断，会把普通身弱误判为从格。

输出应包含：
- 候选格局
- 成格条件
- 破格条件
- 支持证据
- 反证
- 置信度

#### 5. 扩展报告硬规则校验
下一批高价值规则：

- 十神与日主阴阳五行一致性
- 三合、三会、六合、合化成立条件
- 从格破格条件
- 旺衰结论与用神方向冲突
- 月令格局与透干条件
- 大运十神计算一致性
- 前后段落结论矛盾

#### 6. 抗位置偏差采用内容评分，不只加 few-shot
让模型逐项输出"选项内容、支持证据、反证、分数"，最后按最高分映射字母；同一题用不同 shuffle seed 验证一致性。

单纯增加 anti-position few-shot 可能引入新的答案位置模式。

---

### P2：暂缓

#### 7. Graph RAG 和完整多Agent 暂缓
当前没有证据表明引入图数据库或更多 Agent 会直接提高准确率。它们会增加成本和错误传播。

优先完成：结构化命盘规则 → 标准集 → 检索消融。

---

### P3：持续

#### 8. 统一验收指标
后续报告应同时提供：

- BaziQA shuffle-off/on repeats=3
- MingLi-Bench 完整集（非 smoke）
- 旺衰/格局/用神专项准确率
- 检索 Hit@K、MRR
- 真实报告硬错率
- 人工盲审一致率
